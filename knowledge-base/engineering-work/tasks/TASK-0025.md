# TASK-0025: Implement customizable dashboard endpoint (backend)

## Parent Feature

- [FEAT-0008 Customizable Merchant Dashboard](../features/FEAT-0008.md)

## Engineering Specification

- [UI-0004 Tenant Dashboard Foundation and Shell](../../engineering-specifications/specifications/ui/UI-0004.md)
- [BFF - Tenant Dashboard](../../backend/api-endpoints-reference.md)

## Repository Target

- backend/

## Description

Implement `GET /api/v1/merchants/:id/dashboard` (alias `GET /api/v1/bff/tenant/:id/dashboard`) that returns the merchant's dashboard layout resolved from integrations, vertical, and subscription. This is the source of truth for what is integrated and therefore what the dashboard should show.

Current frontend `dukaDesk/src/components/pages/Dashboard.jsx:17` uses local `VerticalContext` and `PRIMITIVES` but does not consider the backend's `GET /api/v1/bff/tenant/:id/integrations` result. The new endpoint must join `tenant.integrations`, `tenant.vertical`, and `tenant.subscription` to produce `{ kpis, quickActions, widgets, enabledModules, layout }`.

## Acceptance Criteria

- [ ] `GET /api/v1/merchants/:id/dashboard` returns 200 with `{ kpis: Array, quickActions: Array, widgets: Array, enabledModules: string[], layout: object }` for the authenticated merchant's tenant. 404 if tenant not found, 401 if unauthenticated, 403 if not owner/member.
- [ ] Logic: `enabledModules = verticalPresetModules(vertical) ∪ integrations.map(i => primitiveForIntegration(i))` filtered by `PRIMITIVE_BY_ID[id].flags` and subscription limits; `kpis`/`quickActions` are sub-selected from `vertical.kpis`/`vertical.quickActions` where `moduleGate` passes.
- [ ] Uses existing `GET /api/v1/bff/tenant/:id/integrations` and `GET /api/v1/merchants/:id/features` as helpers; does not trust client `enabledIds`.
- [ ] Unit test: with `Paystack` enabled → `kpi_revenue` present; without → absent.
- [ ] Integration test: toggle integration via `POST /merchants/:id/integrations/connect` → subsequent `GET /dashboard` reflects change.
- [ ] Docs: update `backend/api-endpoints-reference.md` with the new endpoint and add to `backend/PROGRESS.md` Active Work.
